# A3.0 column-flow prototype evidence

This is an isolated architecture experiment, not a product implementation or a Word-fidelity result. `lib/column-flow-bounds-prototype.ts` is used only by the prototype scripts. The earlier `lib/column-flow-prototype.ts` is retained as the first candidate and is not imported by the application.

The candidate measures a single ProseMirror document at a fixed column width, creates transient line ranges, coalesces adjacent ranges within each region, and positions the existing block ancestors and inline fragments. The editable text exists once; selection and hit testing use the real DOM and ProseMirror's own coordinate methods. Positioned ancestor bounds must follow their rendered descendants, and preserving the source block's content width is essential: a blanket `width:100%` changed list wrapping and made ProseMirror reject a valid native caret as outside its ancestor. Coalescing line ranges avoids introducing a span boundary at every wrapped space. Zero-height tab atoms require line membership based on neighboring caret rectangles rather than treating their baseline as a new line.

The test fixture uses two 260px columns, a 24px gap and 160px region height. These values, its list indentation, and the prototype's physical stack and LTR ordering are fixture assumptions, not the eventual layout model. A region-transition ArrowUp/ArrowDown handler selects the adjacent logical line with the closest relative X and preserves the Shift anchor. Other native keys remain delegated to the browser. The hit area for zero-height tabs is an empty pseudo-element whose prototype bounds come from adjacent line rectangles; it does not add text or change line boxes. Its stack order and font/mark combinations need further coverage.

`node scripts/check-column-flow-bounds.cjs` exercises one editable view, a long marked paragraph and list across multiple columns and pages, sampled caret/hit positions, every nonwhitespace character's measured line, native typing, scroll to the final fragment, zoom and model serialization. Run with `PROTOTYPE_ZOOM=.5` for the second scale. `scripts/check-column-flow-tabs.cjs` uses the real A2 tab plugin and node view, including right and decimal stops in both columns, a wrapped tab with superscript/subscript and a font-size mark, native atom click, adjacent-line hit-area bound and a stability observation. It supplies a fixture-only per-tab geometry resolver and pseudo-element styling. A same-offset unfragmented control is reported when coordinate checks fail. `scripts/check-column-flow-interaction.cjs` exercises browser mouse and keyboard selection, hit testing and scroll. Its range- and direction-matched control run passed 84 of 84 checks at 100% and 50%, including Home/End, cross-region arrows and Shift selection; the report is `/var/folders/j_/6dj4w6pn7qz7wc27v91j3fyw0000gp/T/edtr-column-interaction-LA1yrF/interaction-report.json`. Clipboard serialization uses a synthetic `ClipboardEvent` and composition uses synthetic events and inserted text; neither proves operating-system clipboard or IME behavior.

The A2 API now accepts an optional `resolveTabGeometry(view, paragraphPos, tab, fallback)` callback on `tabLayoutPlugin`; the DOM measurement helper resolves geometry separately for each tab. With no callback, A2 retains its existing behavior. A real A3 implementation must obtain each tab's region-specific origin and width from the shared layout plan, and the ruler must use the caret's region. The fixture adapter is not a production geometry implementation.

The initial relative-inline candidate produced correct-looking text but failed actual PM hit testing on later list content. Making the root page-wide alone did not repair block-boundary rejection. A second-column decimal stop also measured 34px early until the tab's own region origin was used. A wrapped zero-height tab hit the wrong source position although the same offset worked in an unfragmented control; the prototype's measured empty hit area addresses the tested case. These findings motivated the candidate; they are not evidence of general support.

Still required before a product implementation: a bounded, deterministic joint tab/flow measurement and invalidation loop, production-quality typed geometry and ancestor sizing, content changes and composition without destructive DOM churn, mixed sections and real document structures, browser/platform keyboard behavior, the approved Word references, common live/readonly/PDF output, and regression testing. The short observed stable interval in the fixture is not a convergence proof. Synthetic composition is not an operating-system IME test. No RTL, columns break, balancing, table, float or full Word-layout claim follows from this experiment.
