# A7.3 font and authored-spacing evidence

This increment preserves explicit HTML paragraph fonts and a bounded class of CSS line boxes through DOCX export/reopening. It also derives the invisible PDF search-text baseline from the actual browser font box. It does not close A7's remaining font or visible-alignment gates.

## Authored HTML paragraph fonts

A plain HTML paragraph such as `<p style="font-family:Arial;font-size:11pt;line-height:1.15">` previously retained its inline text font but lost the paragraph's font strut. The paragraph then used the editor's 12 pt default base. Explicit family and point/pixel size now remain in the existing `styleText` attribute independently of a linked document style. HTML serialization, storage and paragraph splitting retain that base without resetting inline color or emphasis. DOCX output materializes the base beneath explicit run overrides and on the paragraph mark; DOCX import derives the paragraph base from document defaults, paragraph-style run defaults and direct paragraph-mark family/size, including source-free packages without Normal. Unlinked exports materialize that base into the existing paragraph mark without duplicating its managed properties.

CSS multiples measure em height; Word automatic multiples measure a font's single-line height. Writing an authored CSS 1.15 directly as Word auto 1.15 therefore changes its meaning. For eligible paragraphs the export now writes a fixed point-valued line box: Arial 11 pt × 1.15 becomes 12.65 pt, or exactly 253 twips. The original editor model and HTML keep their CSS multiple. Native Word auto, exact and minimum rules retain their rules and values. Linked style definitions retain automatic spacing semantics; eligible actual paragraphs receive their own exact override.

The Word result has ordinary exact-spacing semantics: later font-size changes in Word keep that fixed point height. Numeric preservation at the exported size does not preserve CSS's dynamic response to later Word-side resizing.

The conversion requires a known Arial/Liberation Sans paragraph base, uniform matching run family and size, ASCII text or ordinary hard breaks, a font size expressible in Word half-points, and a line box expressible in integer twips. Its height must be at least the font's measured single-line metric `(1854 + 434 + 67) / 2048`, conservatively avoiding a short line box. Mixed fonts/sizes, other scripts, inline objects, superscript/subscript, unknown bases and non-integral twips keep the previous conversion fallback. This is deliberately a bounded conversion rather than universal CSS-to-Word fidelity.

`check-authored-line-spacing.cjs` passed in the actual editor. It verifies the 11 pt paragraph base and 12.65 pt computed line height, emphasis/color, end-of-paragraph Enter, persistence, HTML reopening, exact native DOCX values, DOCX reopening with the same 11 pt base and line height, export immutability and the unsupported guards. It also verifies splitting after native exact reopening and splitting mixed-run native auto/exact/minimum paragraphs without a linked style or base-font record. Before clearing the new paragraph's source XML, the split command materializes its effective native spacing; linked-style splitting keeps its existing behavior. `check-word-auto-spacing.cjs` passed native defaults, style/table/direct inheritance, font edits, auto/exact/minimum, persistence and HTML/DOCX roundtrips. `check-paragraph-styles.cjs` passed style application/editing/removal, manual overrides, splitting, margins and native flag serialization. TypeScript and focused lint passed.

## Actual PDF search-text baselines

The PDF artwork remains a browser snapshot. Its invisible search text previously placed its baseline using a fixed 20% em descent. Browser font-box descents vary by actual face, fallback, size, weight and style. The search layer now measures `fontBoundingBoxDescent` using the computed browser font and the actual text segment. Missing Canvas support or non-finite metrics retain the bounded previous fallback. Licensed bundled search fonts and grapheme advances remain separate from the artwork's actual fonts.

`check-pdf-font-baselines.cjs` compares the generated search baseline against native Chromium PDF output for Arial 11/26 pt, Times, Courier, bold italic, missing-family fallback and mixed Arabic/Latin. It also verifies exact-once searchable markers and unsupported Canvas fallbacks. Native Chromium is used only as browser-baseline evidence, never as Microsoft Word evidence. `check-pdf-mixed-text.cjs` separately verifies mixed Arabic/Latin logical text, ActualText spans and DOM glyph positions. Artwork capture and link rectangles/destinations are unchanged by this search-layer change.

For the isolated Courier 11 pt case, the former guess differed from native Chromium's quantized baseline by about 0.519 pt; measuring the actual descent reduced that to about 0.281 pt. Arial 11 pt moved by approximately 0.05 pt. This change does not establish a visible glyph alignment improvement or close the 1 CSS px anchor gate.

The captured Word hhea and OS/2 tables explain the bounded values. Arial and Times use hhea sums of 2355; Calibri's hhea/Windows extent is 2500; Courier's is 2320. Roboto's hhea sum is 2400, but its Windows ascent+descent is 2458. Its actual Word pitches follow 2458, so a hhea-only Roboto profile would be wrong. The listed values are the larger extent for these captured faces; this is not a rule inferred for arbitrary fonts. Licensed Liberation Sans/Serif/Mono aliases and Carlito share the corresponding metric tables, which establishes table compatibility rather than glyph identity.

`check-word-font-profiles.cjs` captures actual renderer faces through Chromium's platform-font API, checks 11 pt paragraph struts and all 15 automatic cases, captures a separate app PDF, preserves native 240/276/360 auto values through DOCX export/reopening, and opens both actual Word-downloaded DOCX files. It also rejects new-profile automatic adjustment for mixed families, non-ASCII runs and independent inline atoms such as tabs or page fields; ordinary hard breaks remain supported. All 15 Word mean pitches fit their recorded metric within 0.079 pt; all 15 captured app mean pitches are within 0.077 pt of Word, approximately 0.103 CSS px. Every explicit line marker occurs once and both PDFs contain five pages. These are measured line-pitch and font-resolution checks, not a glyph-fidelity score.

The new Calibri/Carlito, Times/Liberation Serif, Courier/Liberation Mono and Roboto profiles apply only to uniform ASCII paragraphs. Other scripts, mixed families, independent inline atoms and unknown fonts keep their prior fallback. Existing Arial behavior retains its documented script/fallback limitations. The separate authored exact-spacing conversion remains limited to its initial Arial/Liberation Sans profile; native profile expansion does not silently authorize new authored conversions. No proprietary font binary was copied or published. `APP_FONT_OUTPUT_DIR` redirects application-only PDF/evidence output for isolated production or live validation while preserving the frozen source/reference directory.

The frozen A7.2 expanded column marker residuals remain open. Word's text layer embeds ArialMT and the app's invisible search layer embeds LiberationSans with differing descriptors. Thus text-layer bounds alone cannot diagnose visible alignment; the raster also demonstrates a remaining local difference. No paragraph offset or font metadata has been changed to fit those anchors.
