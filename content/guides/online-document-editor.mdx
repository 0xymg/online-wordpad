An online document editor should support the whole document lifecycle: start a draft, revise it and deliver a usable file. EDTRpad focuses on that workflow for individual writing in the browser.

## Start from text or an existing file

Create a blank document in [EDTRpad](/pad), or choose **File → Open** for a supported file. DOCX import converts content into the editor, so check the result before making changes.

The [DOCX opening guide](/guides/open-docx-online) covers supported formats and conversion limits. Your original file remains separate from the document you are editing.

## Revise for the reader

Use headings to show the document’s structure. Turn repeated fields into a table, and place images near the paragraphs that explain them. Keep formatting consistent rather than changing fonts throughout the page.

Read [rich text editing](/guides/rich-text-editor-online) for a structure-first approach. If several people need to edit simultaneously or leave suggestions, compare the [Google Docs workflow](/guides/google-docs-alternative).

## Deliver the right output

DOCX is an editable handoff; PDF is useful for finished pages; TXT keeps only the words. Export, reopen and review the file before sending it.

Guest autosave is tied to the current browser. An account adds document sync, but exported copies remain useful for portability. Follow [DOCX export](/guides/export-to-word-docx-online) for editable files and [printing](/guides/print-document-browser) for page-layout checks.
